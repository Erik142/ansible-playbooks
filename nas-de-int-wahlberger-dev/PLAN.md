### Assumptions / open risks
- **No live apply this cycle.** Per repo policy for this planning/implementation pass, no task runs `ansible-playbook site.yml` (or `--check`) against `nas.de.int.wahlberger.dev`. Every task's Verification uses static checks only (`yamllint`, `ansible-lint`, `--syntax-check`, `--list-tasks`, `ansible-vault view`, `grep`/`git grep`/`git diff`). All runtime/demonstration acceptance criteria from REQS.md (browser OIDC flows, `curl` against the live host, `podman inspect`/`stats`, reboot, restart-recovery, backup dry runs) are consolidated into T-12, a hardware-validation runbook that is **not executed** by any agent — it requires explicit separate authorization to run against production.
- **Two secrets cannot be generated by any coding task.** `tandoor_oidc_client_id` (plaintext, `vars.yml`) and `vault_tandoor_oidc_client_secret` are issued by Pocket ID only after the operator manually registers Tandoor's OIDC client (primary flow step 1, `roles/tandoor/README.md` per FR-53/73/74). T-09 wires the indirections and leaves these two as empty strings (`""` in `vars.yml` / `vault.yml`) so FR-12's validation fails cleanly and loudly until the operator fills them in by hand — this is expected, not a defect. `tandoor_secret_key` and `tandoor_db_password` (48 hex chars, generator commands in FR-78) *can* be generated and vault-encrypted by T-09 since they need no external party.
- **A-01 through A-04, A-11, A-13 are load-bearing assumptions**, not yet verified against upstream Tandoor docs/release. T-01 is a time-boxed spike whose output (confirmed port, image, Postgres major, OIDC provider id, local-signup/auto-signup coexistence, `/setup/` page closure) gates T-02's defaults and T-08's Homepage ping URL. If T-01 finds A-11 cannot hold (local signup can't stay closed while auto-signup works), REQS.md says "implementation stops and the owner decides" — treat that as a plan-blocking finding, not something to silently work around.
- **Mealie decommission mechanism has no natural home.** FR-39 deletes `roles/mealie/` outright, so the idempotent "stop/remove Mealie's live unit and container" logic (FR-37/38/82) needs a new, small piece of code that isn't `roles/mealie/`. T-06 leaves the exact shape (a minimal `roles/mealie_decommission/` role vs. a `pre_tasks:`-imported task file) to the implementer, constrained only by the CLAUDE.md self-contained-role convention and idempotency; T-09 wires whichever shape is chosen into `site.yml`.
- FR-27/FR-77 (REST API Bearer-token create/read) need no application code — Tandoor's DRF API and token auth are default behaviour once the app and OIDC are deployed. No task builds them; T-12's runbook verifies them against the live instance.
- Renovate already matches `tandoor_image`/`tandoor_db_image`: the existing generic customManager regex `(?:^|\n)\w+_image:\s*"?...` in `renovate.json` matches any `<name>_image:` line in `roles/*/defaults/main.yml`, and the existing "no Postgres major bumps" `packageRules` entry matches on the package name `docker.io/library/postgres`, not per-role — so no `renovate.json` change is needed (FR-08, FR-51, FR-75 are satisfied by following the existing line format, not by editing `renovate.json`).
